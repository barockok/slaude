## v0.40.1 — Slack format fixes: table consistency, link `**` leak, compact UX

Three small bugs surfaced in daily use that each caused visible rendering confusion in Slack. This patch addresses all of them with targeted fixes and expands the format test suite.

### Fixes

- **Tables: always code block.** The table renderer previously switched between a fenced code block (narrow tables) and a definition list (wide tables, >60 chars). This produced inconsistent output — the same data could render differently depending on column widths. Now all tables always render as a fixed-width monospace code block, regardless of width.

- **Link `**` leak after bold links.** `mdToMrkdwn` could emit a dangling `**` immediately after a converted Slack link (e.g. `<url|label>**`). Root cause: when the LLM closes a bold+italic expression with `***` but only opened with `**` (mismatched triple-star close), the bold regex `\*\*…\*\*` consumed the first two stars and left a lone `*` dangling. After sentinel restoration, that lone `*` combined with the restored `C4` bold-close sentinel to form `**` right after the link. Fixed by adding step 4c — a pre-pass that matches `\*\*([^*\n]+?)\*\*\*` and consumes the triple-star close before the emphasis steps can leave anything dangling.

- **`/compact` silent finish.** After a manual `/compact`, the session showed `compacting context…` in the status line but then went completely silent when compaction finished — the only feedback was a ✅ reaction on the original slash command, which is easy to miss. Now the `done` handler checks a `wasCompacting` flag (set when the `compacting` event fires with `trigger: "manual"`) and posts `:white_check_mark: compacted` in-thread before clearing the flag.

### Internal

- 6 new format test cases: bold link (`**[label](url)**`), trailing `***` (`**[link](url)***`), text+link+`***`, link followed by bold, bold-in-label, multiple bold links in one line. Updated the "wide table → definition list" test to expect code block output.
