## v0.40.0 — 1on1 open-mode + reload prompt injection

Two features that round out session control: guests can now be admitted into locked 1on1 threads via natural language, and `reload_session` can fire a follow-up prompt automatically so the agent doesn't need to be poked again after restarting.

### Features

- **1on1: open-mode with LLM-interpreted scope.** The 1on1 session owner can now ask the agent to open the thread to guests (`action:"open"` on `set_one_on_one`). The scope is natural-language (e.g. "let Alice ask anything about the deploy") and is written to a new `open_scope TEXT` column in `one_on_one_locks`. The access gate in `gateway.ts` stays deterministic — it hard-drops non-initiator messages unless `open_scope` is set, at which point the model enforces the constraint from its `<session-mode>` block. `/1on1 open` slash command removed (tool-only); `/1on1 lock` kept for hard re-lock. DB migration included.

- **Reload: optional prompt auto-injection.** `reload_session` now accepts an optional `prompt` arg. When provided, it is queued in `#reloadPrompt` and sent via `sendMessage` immediately after the SDK loop exits — no manual follow-up needed. Prompt-less behaviour is unchanged.
