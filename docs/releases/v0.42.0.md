## v0.42.0 — Horizontal scale: gateway/node split

The centrepiece of this release is the horizontal-scale architecture (spec §7):
slaude can now run as more than one process. A `gateway` process holds Slack
ingress and the control plane; one or more `node` (worker) processes pull jobs
off a Redis queue and call back into the gateway's `/v1` API to do the actual
work. Existing single-process deploys are unaffected — `SLAUDE_ROLE` defaults
to `mono`, today's behavior, and unknown values fall back to `mono` too.

The database layer also gained a driver seam: `SLAUDE_DB=sqlite|pg` switches
between the legacy embedded sqlite and Postgres (`Bun.sql` for a real server,
PGLite for sim/tests), with numbered migrations covering every table in the
horizontal-scale spec plus a one-shot `migrate-sqlite` exporter.

Because this release touches the DB schema, the driver seam, and the agent
dispatch path, it ships as a release candidate first per the project's RC
policy — soak before promoting to stable.

### Features

- **Horizontal scale: gateway/node split (M1–M5).** `SLAUDE_ROLE=gateway|node` (default `mono`) splits Slack ingress/control-plane from queue workers. Nodes call the gateway's `/v1` API over a static bearer token (`SLAUDE_NODE_TOKEN`) plus a short-lived per-job HS256 JWT (`SLAUDE_JOB_SECRET`, header `X-Slaude-Job`) minted on enqueue and verified on the tool-plane and session endpoints. Redis-backed queue (BullMQ-style locks, pubsub, reaper, turn dispatch) with per-node `/healthz` + `/metrics` (`SLAUDE_NODE_PORT`, default 8081) and configurable concurrency (`SLAUDE_NODE_CONCURRENCY`, default 8). ([#95](https://github.com/barockok/slaude/pull/95))

- **Postgres driver seam (`SLAUDE_DB=sqlite|pg`).** `src/db/client.ts` exposes a dialect-agnostic `DbClient` (query/one/run/exec/transaction). sqlite stays the default; `pg` uses `Bun.sql` against a real server (`SLAUDE_PG_URL`) or an in-process PGLite for sim/tests. Numbered migrations under `src/db/migrations/*.sql` cover every table in the horizontal-scale spec (tenants, slack_apps, personas, provider_creds, sessions+tenant_id, pending_gates, seen_events, gateway state, memory_*). The repository layer is now fully async across both dialects.

- **AES-256-GCM column encryption.** `src/db/crypto.ts` encrypts sensitive Postgres columns keyed by `SLAUDE_MASTER_KEY` (32-byte base64), using a versioned `v1:iv:tag:ct` envelope so key rotation can land later without a data migration.

- **`migrate-sqlite` one-shot exporter.** `bun run migrate-sqlite` copies an existing `db.sqlite` into the Postgres target (`SLAUDE_PG_URL`, or a PGLite dir for rehearsal), applying target migrations first. Idempotent via `ON CONFLICT DO NOTHING`; only columns present on both sides are copied.

- **`--skip-schema` migration flag.** Bypasses `initSchema()` on Postgres for write roles that lack `BYPASSRLS` — a superuser pre-applies `schema.sql`, then the data copy runs with `--skip-schema` under the restricted role.

- **`ANTHROPIC_AUTH_TOKEN` support in extractor/model-listing auth.** Gateways authenticated solely via bearer token (no API key, no OAuth) previously failed soul extraction even though the main agent loop already accepted that token. Precedence: API key > OAuth > auth token.

- **Profile-based docker-compose.** Replaces the flat single-service compose file with `brain` (pgvector/pgvector:pg16 + healthcheck), `scale` (redis + worker), and `slaude` (env_file-based secrets, `SLAUDE_DATA_DIR` for the host volume mount) profiles.

### Fixes

- **`fix(agent)`: drain suppress flag on disengaged hook.** When a disengaged thread suppresses a turn, the suppress flag for that turn is now consumed immediately instead of surviving to the next turn, where it was incorrectly firing the mention-only guard on re-engage.

- **`fix(db)`: harden `toPositional` against escapes, comments, and dollar quotes.** The `?`-placeholder rewriter for Postgres now correctly skips single-quoted strings, double-quoted identifiers, line/block comments, and `$tag$`-quoted strings, instead of miscounting placeholders inside them. Repo SQL must use `jsonb_exists(_any/_all)` instead of the JSONB `?`/`?|`/`?&` operators as a result.

- **`fix(db)`: advisory lock serializes concurrent migration boots.** Two processes racing `runMigrations` against an empty Postgres could both attempt the `schema_migrations` bootstrap and crash on a duplicate-key error. The runner now holds `pg_advisory_lock('SLAU', 1)` before any DDL.

- **`fix(db)`: int8 rows as numbers on `Bun.sql`.** `Bun.sql` returns int8 columns as strings by default, causing real-Postgres rows to diverge from PGLite/sqlite. The driver now opens with `bigint: true` and normalizes BigInts to JS numbers.

### Internal

- **Cross-dialect schema drift test.** Diffs the sqlite bootstrap against applied Postgres migrations — a column added on only one side fails CI until mirrored or explicitly allowlisted.
- **`tests/db/pg-real.test.ts`.** Runs the driver contract, concurrent-migration race, and int8 shape parity against a live Postgres server when `SLAUDE_PG_TEST_URL`/`SLAUDE_PG_URL` is set, in throwaway scratch databases.
- New `tests/queue/*` and `tests/node/*` suites covering locks, pubsub, the reaper, turn dispatch, dispatch authority, worker e2e, and shims.
- Docs restructured into a multi-page site; README slimmed to a gateway pointer. ([#94](https://github.com/barockok/slaude/pull/94))
