## v0.39.1 — Fix stale projects/ symlink surviving agentConfigDir() correction

Patch release closing the last gap in the `/1on1` session-continuity fix from v0.39.0.

### Fixes

- **1on1: detect and replace stale `projects/` symlink on lock flip.** v0.39.0 corrected `agentConfigDir()` to return `~/.claude` instead of `paths.claudeConfig` (`~/.slaude/.claude`), so newly created initiator dirs get a correct `projects/` symlink. However, initiator dirs created *before* v0.39.0 already had a symlink pointing at the old wrong target (`/data/.claude/projects`). `ensureInitiatorConfigDir()` only checked `existsSync(dstProjects)` — any existing entry, correct or stale, was left as-is. Result: the v0.39.0 fix had no effect on any initiator whose dir was created before the upgrade.

  Fix: `lstatSync` the dst path. If it's a symlink with a `readlink` target that doesn't match `srcProjects`, `unlink` and recreate. Real directories (legacy initiator homes with transcripts already inside) are still left untouched — only wrong symlinks are replaced.

  Also adds a regression test (`replaces a stale symlink pointing at the wrong target`) to the `ensureInitiatorConfigDir` suite. ([findings](../findings/2026-06-11-1on1-transcript-sharding.md))
