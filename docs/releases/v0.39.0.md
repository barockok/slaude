## v0.39.0 — Silent skill evolution + 1on1 session continuity fix

Two improvements: proactive skill-saves now stay silent unless the change is genuinely new or meaningful, and switching an existing session to `/1on1` mode now correctly continues the conversation instead of cold-starting.

### Features

- **Runtime: silent proactive skill-saves by default.** The runtime-baseline now includes a rule governing when auto-evolve skill writes should reply to the user. Routine refinements and minor auto-evolve evaluations stay silent — only genuinely new capabilities or changes that materially affect future interactions surface a reply. This cuts low-signal "saved /slug" noise from threads without suppressing writes that users should know about. (#82)

### Fixes

- **1on1: correct `agentConfigDir()` fallback so `projects/` symlink targets real transcript home.** When `/1on1` is enabled (or released) in an existing session, slaude reboots the claude-code child with a new `CLAUDE_CONFIG_DIR` pointing at the per-initiator OAuth home. A `projects/` symlink inside that dir was supposed to bridge back to the agent's transcript store so `resume` could find the existing conversation. The symlink target was `paths.claudeConfig` (`~/.slaude/.claude`) — a directory that doesn't exist because unlocked sessions never set `CLAUDE_CONFIG_DIR`, leaving the CLI to use its own built-in default (`~/.claude`). Result: every `/1on1` toggle was a cold start; the old conversation was silently orphaned. Fix: `agentConfigDir()` now falls back to `join(homedir(), ".claude")` — the CLI's actual default — so the symlink correctly points at `~/.claude/projects/` where unlocked transcripts live. Also updated `tests/setup.ts` to set `CLAUDE_CONFIG_DIR` to the temp test home, isolating tests from the real `~/.claude` and fixing 4 previously broken oauth-home tests. ([findings](../findings/2026-06-11-1on1-transcript-sharding.md))
