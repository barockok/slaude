## v0.44.0 — webhook mode boots without a registered app

A small release fixing a real operational rough edge: `SLAUDE_SLACK_MODE=http`
required the Slack app to already be registered before the gateway process
was allowed to start, which doesn't fit an orchestrator that brings the
process up first and registers against it afterward. Also fixes a CI flake
traced to its actual root cause during this release's own review.

### Features

- **Boot http mode with an empty `slack_apps` registry (#112).** Previously,
  `SLAUDE_SLACK_MODE=http` with no app registered and no OAuth install
  enabled hard-failed at boot:
  `SLAUDE_SLACK_MODE=http but the slack_apps registry is empty`. That forced
  a specific ordering — `bun run slack-app add` had to succeed against
  Postgres before the gateway was ever allowed to start.

  Boot now logs and waits instead, the same way the OAuth-install path
  already handled an empty registry. A new `ensureRegistryLoaded()` re-queries
  the registry once when it's still empty, called on every inbound
  `/slack/events`/`/slack/interactions` request, so `bun run slack-app add`
  run from a separate process against the same Postgres is picked up on the
  very next request — no restart needed. See [Webhook (Events API)
  mode](../deploy/webhook-mode.md).

### Fixes

- **Multi-node sim: session lock TTL was too tight for CI headroom.** The
  sim's session lock (`ttlMs: 2000, extendEveryMs: 300`) left almost no
  margin on a loaded shared CI runner — a single stall past ~2s (GC pause,
  event-loop block, one slow Redis round-trip) lost the lock outright and
  aborted the turn mid-scenario. Reproduced 6/6 times in a row on an unrelated
  PR before being traced to this: `approval-authz.yaml`, the only scenario
  with two sequential human clicks, has by far the longest wall-clock gap of
  any scenario in the suite, which is why it was the one that reliably
  tripped it. Raised to `ttlMs: 10_000, extendEveryMs: 1_500` in both call
  sites (`src/gateway/sim/cluster.ts` and the mirrored copy in
  `tests/integration/harness.ts`). Verified with 3 clean multi-node sim runs
  (26/26 scenarios each) against freshly recreated Postgres + Redis
  containers.
