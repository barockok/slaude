## v0.37.0 — /bash command, cron silence fix, plain-text task markers

Three targeted improvements to operator control, cron autonomy, and task display fidelity.

### Features

- **Gateway: `/bash` slash command.** Manager and backup manager can now run shell commands directly from Slack with `/bash <command>`. Output (stdout + stderr) is posted back to the thread, capped at 2800 chars with a truncation notice. Accepts plain text, backtick-wrapped, or triple-backtick fenced input; Slack URL encoding is decoded before exec so copied URLs work as-is. No approval gate — restricted to manager identities only. ([#78](https://github.com/barockok/slaude/pull/78))

- **Cron: exempt sessions from stop-guard reply enforcement.** Cron jobs are autonomous background runs where the prompt itself decides whether to post (e.g. "keep silent if nothing new"). The stop-guard's force-reply instruction was overriding that intent, causing the agent to post to Slack even when told not to. Fix: cron `SessionRoute`s are now marked `silent: true`, which the stop guard skips. ([#77](https://github.com/barockok/slaude/pull/77))

### Fixes

- **Tasks: plain-text task markers.** Unicode checkmarks (✔ U+2714, ✅) rendered as emoji in Slack, breaking the intended plain-text status display. Switched to ✓ (U+2713) for completed tasks and ➠ for in-progress — both render as plain characters in Slack. ([#79](https://github.com/barockok/slaude/pull/79))
