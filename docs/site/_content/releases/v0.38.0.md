## v0.38.0 — Unified skill surface + brain rescue

Two focused improvements: skills now appear in the agent's context automatically without needing an explicit `list_skills` call, and `kb_think` no longer silently fails when `runThink`'s internal gather misses pages that actually exist.

### Features

- **Agent: unified skill surface via SDK plugin.** `~/.slaude/` is now always mounted as a local SDK plugin with `skipMcpDiscovery`. Because `~/.slaude/skills/<slug>/SKILL.md` already follows the Claude Code plugin skill layout, the SDK discovers those skills and injects them into `<system-reminder>` each turn. The agent no longer needs to call `list_skills` to know what skills are available — they're passively visible. The Slack `/slug` expansion path is unchanged. This collapses two parallel skill-discovery tracks into one unified flow. ([#80](https://github.com/barockok/slaude/pull/80))

### Fixes

- **Brain: rescue synthesis when `runThink` gather misses.** `kb_think` was returning `pagesGathered: 0` ("nothing in KB") for pages that `kb_search` found immediately. Root cause: gbrain's `runThink` anchors its vector search to `sourceId` and applies `allowedSources` as a post-filter — pages stored under a different source slice are skipped even when allowed. The slaude-side `gather()` fan-out (one search per source, each anchored correctly) surfaces them. Fix: when `runThink` gathers zero pages but the cross-check `gather()` finds hits, slaude now synthesises an answer directly from those pages and returns it with `gather_rescue: true`. The underlying gbrain scoping issue is upstream and tracked for a future fix. Additionally, the cross-check's silent `catch {}` was replaced with a logged warning so cold-start exceptions are diagnosable rather than invisible. ([#81](https://github.com/barockok/slaude/pull/81), [findings](../field-notes/2026-07-27-kb-think-gather-miss.md))
