## v0.42.1 — Knowledge Base & Embedding Migration Resilience

This maintenance release brings self-healing embedding dimension migrations and provider-driven embedding resolution to the v0.42 line, enabling seamless migration to modern embedding models (such as Google Gemini `text-embedding-004`) without process deadlocks or manual database interventions.

### Features

- **Provider-Driven Embedding Resolution.** Decouples embedding configuration from hardcoded provider dictionaries. Operators can configure embedding using `EMBEDDING_PROVIDER` and `EMBEDDING_MODEL`, supporting canonical resolution for `google`, `openai`, `voyage`, `zeroentropyai`, and `litellm`.
- **Asymmetric Embedding & Google Gemini Support.** Native support for `google:text-embedding-004` (768 dimensions) with task-specific retrieval modes (`RETRIEVAL_QUERY` vs `RETRIEVAL_DOCUMENT`).
- **Self-Healing Vector Dimension Drift.** Automatically detects changes in configured embedding dimensions (e.g., migrating from 1280-dim ZeroEntropy to 768-dim Gemini). The brain backs up the incompatible PGLite store to `db.<dimensions>.bak`, reinitializes clean vector tables at the new dimension width, and triggers background re-indexing.

### Fixes

- **PGLite Startup & Lock Takeover.** At container boot, cleans leftover `.gbrain-lock` directory and `postmaster.pid` from previous dirty shutdowns, preventing startup deadlocks and timeout failures during pod restarts.
- **Root-Level Wiki KB Support.** Resolves knowledge base loading when markdown pages reside at the repository root rather than under a nested `wiki/` subdirectory.
- **Search Query Normalization.** `normalizeQuery` cleans excess whitespace and trailing punctuation while preserving exact technical terms and identifiers.
