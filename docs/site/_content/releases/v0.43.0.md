## v0.43.0 — a control panel for operators, and a docs site that stops rotting

The headline is a full operator web console for the horizontal-scale gateway —
watch every session live, take control of one from Slack, drive it directly.
Alongside it: the docs site's generated HTML stopped being committed (it was
quietly desyncing from its own Markdown), two dedicated deploy guides landed
for features that only existed as reference-table rows, and Postgres
migrations gained an escape hatch for deploys that apply schema out of band.

### Features

- **Session control panel — gateway web dashboard (#96).** An operator web
  console at `/panel` (`SLAUDE_PANEL=1`, `mono` or `gateway` role, never
  `node`): a fleet list across every persona and node with status-dot triage
  and context-window meters, a session detail view with fenced destructive
  controls (stop, reset, model switch, permission-mode change, `/1on1`
  unlock), a live typed event timeline over SSE, and a chat surface that talks
  to the session directly. Chatting or locking a session takes over its
  *active surface* — inbound Slack for that thread defers and replays on
  release, the agent's Slack-bound replies suppress while an operator drives.
  Auth is the panel's own OIDC relying party (Authorization Code + PKCE,
  self-issued 15-minute/8-hour session tokens); it keeps no operator records
  of its own — identity comes from an ID-token claim, roles from a file or an
  env list re-resolved per request. Cross-replica correctness (deferred-inbound
  replay, outbound-suppression, force-release-as-transfer) is coordinated over
  Redis and covered by a dedicated two-replica integration suite. See
  `docs/site/_content/deploy/panel.md` and
  `docs/site/_content/field-notes/2026-08-29-panel-oidc-auth.md`.

- **`SLAUDE_MIGRATE_ON_BOOT` toggle (#110).** Postgres migrations have always
  applied automatically on boot — the right default, since it's what makes a
  fresh Postgres usable with no separate migrate step. `SLAUDE_MIGRATE_ON_BOOT=0`
  now opts a deploy out, for the case where migrations run out-of-band ahead of
  a rollout and every gateway replica should skip the advisory-lock wait
  entirely. Default stays on; sqlite is unaffected. Also documents
  `SLAUDE_MIGRATE_LOCK_TIMEOUT_SEC`, which existed in code with no
  `configuration.md` row.

### Docs

- **Generated HTML is no longer committed (#108).** The docs generator used to
  write HTML in place next to its own Markdown sources, so 113 generated files
  lived in the repo, `search-index.json` conflicted on nearly every rebase, and
  nothing enforced that committed HTML actually matched the Markdown it
  claimed to render. `docs/site/build.mjs` now writes to a gitignored
  `docs/site/_site/`, wiped and rebuilt every run; the Pages workflow builds
  and publishes it directly, and a new CI job builds the site on every PR so a
  broken internal link fails before merge instead of showing up as a silently
  stale deploy. Also fixed: eleven pages were rendering their title twice (the
  template's H1 plus the Markdown's own leading H1) — the nav-declared pages
  now get the same H1-stripping treatment discovered pages already had, and
  an archived field note's mis-leveled `#` sections are now `##`.

- **Webhook (Events API) mode and Control panel guides (#109).** Both features
  existed only as dense reference-table rows or a bullet buried in a
  horizontal-scale section — nothing walked through actually turning them on.
  New `docs/site/_content/deploy/webhook-mode.md` covers prerequisites,
  registering a Slack app (manual or OAuth install), generating the http-mode
  manifest, and troubleshooting. New `docs/site/_content/deploy/panel.md`
  covers what the panel does and its OIDC setup, moved out of
  `deploy/multi-node.md` since the panel runs the same way in `mono` role and
  needs no scale-out at all.

- **Manifest sample gained the Canvas, pin and topic scopes (#105).** The
  Slack app manifest's OAuth scope list in `configuration.md` was missing
  `canvases:write`, `channels:manage`, `groups:write` and `pins:write` —
  scopes the shipped tool surface (`create_canvas`, `pin`, `set_topic`, etc.)
  has needed since #100 but the manifest generator never requests. Tracked as
  a code gap in #104; this release only updates the docs sample.
