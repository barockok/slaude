What a folk is made of

A persona you write. A runtime that keeps it honest.

You author one file. The runtime supplies the discipline: how it speaks in Slack, when it asks, what it never does. Neither layer can override the other.

Soul

Name, role, voice, manager, mandate, approvers. One markdown file at ~/.slaude/SOUL.md. The model reads it; the gateway checks every id it returns against the raw text.

Skills

Capabilities as files. A folk writes its own skill when it learns a new job, and syncs it to git so it survives a redeploy. Invoke any of them with /skill-name.

Memory

Episodic and semantic. What happened in a thread, and what it learned from it. A knowledge base it can search, think over, and write back to with an audit trail.

Approvals

Before anything mutates, it asks. Approve and Deny buttons land in the thread. Who may approve what comes from the soul, never from the model.

One runtime, many folks

Same silhouette. Different face. Their own Slack identity.

Every persona is a deployment with its own soul, its own memory, and its own Slack user. They can sit in the same channel and hand work to each other. Pick one below.

Each persona is one container with one SOUL.md. Adding a folk is adding a deployment, not a config flag.

Gateway and node mode

One socket to Slack. As many workers as the week needs.

The gateway holds the Slack connection, the trust boundary, and the approval gate. Nodes run the agents. Add a node when the queue grows. Drain one when it does not. Slack never notices.

Where it happens

The thread is the session.

Mention a folk and the thread is engaged. Come back tomorrow and it still knows. Mention somebody else and it steps out.

  • One Slack thread maps to one persistent session, resumed across restarts.
  • Replies go through the runtime, never streamed raw. Markdown becomes Slack mrkdwn.
  • Lock a thread to yourself and the manager with /1on1.
  • Try all of it without a workspace: the simulation gateway runs the same code in memory.

Install

Five minutes to a first DM.

Folks is the friendly name. The runtime is slaude, and the commands still say so.

# one line, pinned release, Bun installed for you if missing
curl -fsSL https://raw.githubusercontent.com/barockok/slaude/main/install.sh | bash

# give your first folk a face
slaude init            # writes ~/.slaude/SOUL.md and .env to fill
slaude manifest        # paste into api.slack.com/apps → From manifest
slaude start           # or: docker compose up -d
