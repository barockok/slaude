v0.41.0

v0.41.0 — Multi-persona: one process, N Slack identities#

The centrepiece of this release is multi-persona support. A single slaude process can now operate as multiple distinct Slack users simultaneously — each with its own SOUL.md, brain slice, xoxp posting identity, reaction client, MCP OAuth tokens, and session transcripts. Routing is automatic: incoming messages are dispatched to the correct persona session based on which bot was mentioned.

The release also switches the brain storage layer to a configurable backend (SLAUDE_BRAIN_ENGINE) and ships promote-rc.sh to tighten the release candidate pipeline.

Features#

  • Multi-persona (Phase 1): one process, N Slack user identities. ~/.slaude/personas/<name>/ directories define additional personas. Each persona gets its own SOUL.md, agent-<id> brain slice, and isolated DB session rows (persona_id column). Mention routing dispatches to the right session automatically. (#76↗)

  • Multi-persona (Phase 2): per-persona xoxp posting. When a persona has its own SLACK_USER_TOKEN, messages and slash-command replies are posted from that user identity rather than the shared bot token. The persona name appears in Slack as a real user, not an app.

  • Per-persona reactions. Each persona uses its own xoxp client for emoji reactions, so :eyes: and :white_check_mark: show up from the correct Slack identity.

  • Per-persona MCP isolation. MCP OAuth tokens and session transcripts are scoped under ~/.slaude/personas/<name>/.claude/ — named personas no longer share credentials or commingle transcripts with each other or with the default session. See findings: 2026-07-27 multi-persona phase 1.5.

  • Brain engine selection (SLAUDE_BRAIN_ENGINE). Set SLAUDE_BRAIN_ENGINE=postgres to run the brain against a real Postgres instance instead of the default PGLite embedded DB. Useful for multi-process or multi-replica deployments where the brain must be shared.

  • PGLite → Postgres migration script. scripts/migrate-brain-pglite-to-pg.ts dumps all brain pages from an existing PGLite DB and loads them into Postgres in a single pass.

Fixes#

  • fix(surface-mcp): remove lock from set_one_on_one agent tool. The LLM can no longer initiate a 1on1 lock via the tool. Only the /1on1 slash command can start a session. The tool retains open (set guest scope) and off (exit). Prevents an agent from locking a thread without user intent.

  • fix(mention-only): halt model via hook, not just envelope text. The disengage suppressor now fires a UserPromptSubmit hook returning continue:false to stop the model, rather than relying solely on the envelope flag which could be bypassed.

  • fix(format): exclude * from URL token. Bold markdown wrapping a URL (**url**) no longer eats the trailing ** into the URL token. Fixes broken bold-URL formatting in Slack output.

  • fix(agent): suppress abort error on intentional session stop. The error event emitted on AbortError when a session was intentionally aborted is no longer surfaced, removing spurious error log noise.

  • fix(persona): strip persona mention before slash command parsing. When a named persona is @-mentioned before a slash command (e.g. @Alice /compact), the mention is stripped before the command parser runs so the slash is correctly recognised.

  • fix(persona): use persona xoxp client for slash command replies. Slash commands (/1on1, /model, etc.) now reply from the persona's own Slack identity when one is configured.

  • fix(persona): thread persona name through /mcp connect token persist. The OAuth token store uses the correct persona identity when persisting MCP connection tokens from a named-persona session.

Internal#

  • ci: shellcheck every tracked shell script. CI now lints all .sh files in the repo via shellcheck. Catches quoting/portability issues before merge.

  • scripts/promote-rc.sh. Automates the RC → stable promotion: validates preconditions (tag exists, stable absent, clean main, notes file present), prints unsoaked commits, bumps package.json, commits, tags, and pushes on confirmation. See findings: 2026-08-23 release-candidate-pipeline.

  • fix(test): reset brain state before brain-coverage suite. Prevents state leakage between test runs that was causing flaky failures.

  • fix(ci): serialize test-file execution. Brain-coverage tests now run in a fixed order to eliminate race-condition flakiness in CI.
